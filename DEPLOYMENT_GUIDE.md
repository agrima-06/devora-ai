**System:** Devora AI  
**Deployment Model:** Frontend on Vercel + Backend on Render + Managed PostgreSQL 16 (pgvector)

---

## 1. Prerequisites Checklist

Before beginning deployment, ensure you have:
- [ ] A GitHub account with access to the Devora AI repository.
- [ ] A [Render](https://render.com) account (for Docker backend and PostgreSQL).
- [ ] A [Vercel](https://vercel.com) account (for Next.js 14 frontend).
- [ ] A Google Cloud / Gemini API key (optional; falls back to mock if absent).
- [ ] A domain name (e.g. `devora.ai`) with DNS access (optional for custom domains).

---

## 2. Step 1: Provision Managed PostgreSQL 16 with pgvector

You can use **Render PostgreSQL**, **Neon Serverless Postgres**, or **Supabase**.

### Option A: Render PostgreSQL (Recommended for Simplicity)
1. In the Render Dashboard, click **New +** $\to$ **PostgreSQL**.
2. Name: `devora-postgres`.
3. Database Name: `devora`.
4. User: `devora_user`.
5. Version: **16**.
6. Plan: **Starter** ($7/mo) or Free.
7. Click **Create Database**.
8. Once provisioned, copy the **Internal Database URL** (for Render services) and **External Database URL** (for local migration execution).

### Option B: Neon / Supabase
1. Create a PostgreSQL 16 project.
2. In the SQL Editor, verify `pgvector` is available:
   ```sql
   CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
   CREATE EXTENSION IF NOT EXISTS "vector";
   ```
3. Copy the pooled connection string (with SSL mode enabled: `?sslmode=require`).

## 3. Step 2: Execute Production Database Migrations

Never run migrations against production without a verified connection string and pre-flight check.

### Migration Procedure:
1. From your local environment or CI runner:
   ```bash
   # Set target production database URL
   export DATABASE_URL="postgresql+asyncpg://devora_user:your_password@your-db-host:5432/devora?ssl=require"

   # Dry-run SQL preview (verify no destructive DROP statements)
   .venv/bin/alembic upgrade head --sql

   # Apply all 16 migrations
   .venv/bin/alembic upgrade head
   ```
2. Verify migration state:
   ```bash
   .venv/bin/alembic current
   # Expected output: 016_benchmark_engine (head)
   ```

## 4. Step 3: Deploy Backend API to Render

### Method 1: 1-Click Blueprint Deploy (Recommended)
1. In the Render Dashboard, navigate to **Blueprints**.
2. Connect your GitHub repository: `https://github.com/agrima-06/devora-ai.git`.
3. Render detects `render.yaml` and provisions:
   - `devora-postgres` (PostgreSQL 16)
   - `devora-backend` (Docker Web Service)
   - `devora-worker` (Docker Background Worker)
4. Populate secret environment variables:
   - `GEMINI_API_KEY`: Your Gemini API key.
   - `SECRET_KEY`: Automatically generated by Render, or paste `openssl rand -hex 32`.
   - `SHOWCASE_MODE`: `true`.
5. Click **Apply**.

### Method 2: Manual Web Service Setup
1. In Render Dashboard, click **New +** $\to$ **Web Service**.
2. Connect the repository `devora-ai`.
3. Select **Docker** environment.
   - **Docker Command / Context:** `backend`
   - **Dockerfile Path:** `backend/Dockerfile`
4. Set Environment Variables:
   ```env
   ENVIRONMENT=production
   SHOWCASE_MODE=true
   PORT=8000
   DATABASE_URL=postgresql+asyncpg://... (from Step 1)
   SECRET_KEY=<64-char-hex-key>
   BACKEND_CORS_ORIGINS=https://app.devora.ai,https://devora.vercel.app,http://localhost:3000
   GEMINI_API_KEY=AIzaSy...
   GEMINI_MODEL=gemini-2.5-flash
   USE_MOCK_LLM=false
   DEVORA_MOCK_GITHUB=true
   ```
5. Set Health Check Path: `/health`.
6. Click **Create Web Service**.
7. Once live, test health endpoint:
   ```bash
   curl -i https://your-backend-subdomain.onrender.com/health
   # Expected: HTTP 200 {"status": "healthy", "services": {"database": "connected"}}
   ```

## 5. Step 4: Deploy Frontend to Vercel

1. In the [Vercel Dashboard](https://vercel.com), click **Add New...** $\to$ **Project**.
2. Import `devora-ai` from your GitHub account.
3. Configure Project Settings:
   - **Framework Preset:** Next.js
   - **Root Directory:** Edit $\to$ select `frontend`
   - **Build Command:** `npm run build`
   - **Output Directory:** `.next`
   - **Install Command:** `npm install`
4. Configure Environment Variables:
   - `NEXT_PUBLIC_API_URL`: `https://your-backend-subdomain.onrender.com` (Your live Render backend URL).
5. Click **Deploy**.
6. Vercel compiles all 17 static and dynamic pages. Once finished, your application is live at `https://devora-ai.vercel.app`!

---

## 6. Step 5: Configure Custom Domains and CORS (Optional)

1. **Frontend Custom Domain:**
   - In Vercel Project Settings $\to$ **Domains**, add `app.devora.ai`.
   - In your DNS provider (Cloudflare, Namecheap, GoDaddy), create a `CNAME` record:
     - Name: `app`
     - Value: `cname.vercel-dns.com`
2. **Backend Custom Domain:**
   - In Render Web Service Settings $\to$ **Custom Domains**, add `api.devora.ai`.
   - In your DNS provider, create a `CNAME` record:
     - Name: `api`
     - Value: `your-backend-subdomain.onrender.com`
3. **Update CORS Allowlist:**
   - In Render Environment Variables, update `BACKEND_CORS_ORIGINS`:
     ```env
     BACKEND_CORS_ORIGINS=https://app.devora.ai,https://devora.vercel.app
     ```

## 7. Step 6: Post-Deployment Smoke Verification

Run the following checks against your live deployment:

1. **Backend Health Check:**
   ```bash
   curl -s https://api.devora.ai/health | jq .
   ```
2. **User Authentication:**
   Navigate to `https://app.devora.ai/signup`, create a demo account, and verify successful redirect to `/dashboard`.
3. **Architecture & Refactoring Exploration:**
   Navigate to `/refactoring`, `/drift-debt`, `/monorepo`, and `/repository-graph`. Confirm graph nodes and metrics render.
4. **Benchmarks & Calibration:**
   Navigate to `/benchmarks`, inspect the 31 ground-truth scenarios, verify that Category G security policies display unredacted metadata while protecting ground truth.
5. **SSE Live Streaming:**
   Create an autonomous task and confirm live status transitions appear in the task execution console without buffering.

## 8. Rollback & Emergency Procedures

- **Database Rollback:**
  To revert the last applied migration:
  ```bash
  .venv/bin/alembic downgrade -1
  ```
- **Backend Rollback:**
  In Render Dashboard $\to$ **Deploys**, select the previous successful build and click **Rollback to this deploy**.
- **Frontend Rollback:**
  In Vercel Dashboard $\to$ **Deployments**, select the previous working deployment and click **Instant Rollback**.
